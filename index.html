ความสำคัญของระบบข้อมูลสุขภาพในยุคดิจิทัล

การเข้าใจระบบสารสนเทศโรงพยาบาล (HIS) คือการเข้าใจ กระแสข้อมูล (Data Flow) ตั้งแต่แพทย์บันทึกเวชระเบียน ณ จุดบริการ ไปจนถึงการส่งออกข้อมูลเพื่อประมวลผลตัวชี้วัดระดับประเทศ การเบิกจ่ายงบประมาณ และการวางนโยบายสาธารณสุข

ข้อมูลสุขภาพ (Health Information) คืออะไร

แบ่งออกเป็น 2 กลุ่มหลักที่เกิดขึ้นในระบบบริการของโรงพยาบาล

1. ข้อมูลด้านการแพทย์และผู้ป่วย
  • ข้อมูลส่วนตัวของผู้ใช้บริการและการลงทะเบียน
  • ข้อมูลการรักษาพยาบาลและประกอบการวินิจฉัยโรค
  • ข้อมูลยาและการสั่งจ่ายยา
  • ข้อมูลภาพถ่ายรังสี (PACS) และผลห้องปฏิบัติการ (LIS)
  • ข้อมูลงานวิจัย เคสคดีความ และข้อมูลประกัน
2. ข้อมูลระบบบริหารภายในโรงพยาบาล
  • ข้อมูลการเงิน การบัญชี และข้อมูลทางธุรกิจ
  • ข้อมูลบุคลากรทางการแพทย์และบุคลากรทั่วไป
  • ข้อมูลคลังยา เวชภัณฑ์ และทรัพย์สินต่าง ๆ
  • ข้อมูลระบบคอมพิวเตอร์ (Source code / Password / IP)

วัตถุประสงค์การเรียนรู้ 8 ข้อ

OBJECTIVE 01

เข้าใจความสำคัญของ HIS และคลังข้อมูล HDC กระทรวงสาธารณสุข

OBJECTIVE 02

รู้จักประเภทข้อมูลสุขภาพ และรูปแบบการจัดเก็บข้อมูลในระบบ

OBJECTIVE 03

เข้าใจหลักการให้รหัสโรคมาตรฐาน ICD-10 และ SNOMED CT

OBJECTIVE 04

รู้จักโครงสร้างข้อมูลมาตรฐาน 43 แฟ้ม และรหัสมาตรฐานภายในแฟ้ม

OBJECTIVE 05

รู้จักเทคโนโลยีการบันทึก รวบรวม ส่งออก และวิเคราะห์ข้อมูล

OBJECTIVE 06

รู้จักตัวชี้วัดทางสุขภาพที่สำคัญในบริการสุขภาพปฐมภูมิ

OBJECTIVE 07

อธิบายบทบาทหน้าที่ของแพทย์และบุคลากรต่อระบบข้อมูลสุขภาพ

OBJECTIVE 08

บอกความเสี่ยงที่สำคัญของระบบข้อมูลสุขภาพ และแนวทางการควบคุม

กำหนดการและสถานที่ศึกษาดูงาน

ชั่วโมงที่ 1 • หน้างานบริการ

ห้องตรวจ OPD, ER ชั้น 1 ตึกอุบัติเหตุฉุกเฉิน, ห้องบัตร, ห้องยา, งานเคลม

ประเด็นที่ควรสังเกต: จุดเกิดข้อมูล (Point of care) การลงทะเบียน การบันทึกเวชระเบียน การสั่งยา และการส่งข้อมูลเบิกจ่าย

ชั่วโมงที่ 2–3 • ระบบหลังบ้านและวิเคราะห์

ศูนย์คอมพิวเตอร์ และห้องเรียน

ประเด็นที่ควรสังเกต: โครงสร้างระบบ HIS ฐานข้อมูล การส่งออก 43 แฟ้ม Dashboard และการบริหารความเสี่ยงด้าน IT

บทที่ 1 • MODULE 01

โครงสร้างระบบข้อมูลสุขภาพและมาตรฐานข้อมูล

สถาปัตยกรรมระบบสารสนเทศโรงพยาบาล (HIS) การจัดเก็บฐานข้อมูลด้วยภาษา SQL คลังข้อมูลกลาง HDC มาตรฐานโครงสร้าง 43 แฟ้ม และการเชื่อมโยงข้อมูลข้ามโรงพยาบาล (HIE)

1.1 องค์ประกอบย่อยของระบบสารสนเทศโรงพยาบาล (HIS)

ตัวอย่างซอฟต์แวร์ HIS ในไทย เช่น HOSxP (รพ.พุทธชินราช พิษณุโลก พัฒนาโดย BMS), JHCIS (หน่วยปฐมภูมิ), HoMC, PMK, Panacea โดยเชื่อมโยง 5 ระบบย่อยเข้ากับฐานข้อมูลกลาง:

EHR / EMR / PHR

ระบบบันทึกข้อมูลเวชระเบียนและการตรวจรักษาผู้ป่วย

ระบบยา (Pharmacy)

การสั่งยาของแพทย์ การจ่ายยา และการบริหารคลังยา

ระบบห้องแล็บ (LIS)

Laboratory Information System ส่งตรวจและรายงานผลแล็บ

ระบบรังสี (PACS)

ระบบจัดเก็บและแสดงผลภาพถ่ายทางรังสีวิทยา

ระบบ Back Office

การเงิน บุคลากร คลังพัสดุ ซ่อมบำรุง (เช่น เชื่อมต่อ SAP)

1.1.2 ฐานข้อมูลเชิงสัมพันธ์ (SQL) และการทำ Normalization

จัดการด้วย MySQL, MS SQL Server, Oracle หรือ PostgreSQL โดยแยกตารางตามประเภทข้อมูลแล้วเชื่อมกันด้วยรหัสอ้างอิง (Key) เช่น HN เพื่อลดความซ้ำซ้อนและความผิดพลาด:

1.2 คลังข้อมูล HDC และโครงสร้างมาตรฐาน 43 แฟ้ม

ทุกหน่วยบริการต้องส่งข้อมูลตามโครงสร้าง 43 แฟ้ม เข้าสู่ Health Data Center (HDC) เพื่อใช้ติดตามผลงานและจัดสรรงบประมาณ (Capitation):

แฟ้ม PERSON

เก็บข้อมูลประชากรเบื้องต้น (เช่น รหัสคำนำหน้า "นาย" = 003, "ด.ช." = 001)

แฟ้ม CHRONIC

เก็บประวัติผู้ป่วยโรคเรื้อรังในพื้นที่รับผิดชอบ เพื่อการดูแลต่อเนื่อง

แฟ้ม DIAG (DIAGNOSIS_OPD)

เก็บข้อมูลการวินิจฉัยโรคด้วยรหัส ICD-10-TM และประเภทการวินิจฉัย (DIAGTYPE 1–7)

แฟ้ม DRUG

เก็บข้อมูลรายการสั่งจ่ายยาและเวชภัณฑ์ให้แก่ผู้มารับบริการ

แฟ้ม EPI

เก็บข้อมูลการได้รับวัคซีนสร้างเสริมภูมิคุ้มกันโรค

แฟ้ม SPECIALPP / DEATH / HOME

รหัสคัดกรองพิเศษ (เช่น บุหรี่ไฟฟ้า = 1B572), สถานที่ตาย และสุขาภิบาลหลังคาเรือน

1.3 การเชื่อมโยงและแลกเปลี่ยนข้อมูลสุขภาพ (HIE & API)

แพลตฟอร์มอย่าง Health Link ช่วยให้ดูประวัติข้ามสถานพยาบาล ลดการตรวจแล็บซ้ำซ้อน ลดการแพ้ยาซ้ำ โดยสื่อสารระหว่างระบบต่าง Vendor ผ่าน API:

1. Client (ผู้ขอข้อมูล)

ระบบ HIS ของโรงพยาบาลปลายทางส่งคำขอเรียกดูประวัติผู้ป่วย

2. API (ตัวกลางแลกเปลี่ยน)

Application Programming Interface แปลคำขอและส่งข้อมูลตามมาตรฐานกลาง

3. Server (ฐานข้อมูลต้นทาง)

ตรวจสอบสิทธิ์และส่งข้อมูลประวัติการรักษากลับไปยังผู้ขออย่างปลอดภัย

2.4 Clinical Coder (ผู้ให้รหัสโรค)

การประมวลผลกลุ่มวินิจฉัยโรคร่วม (DRG) และค่าดัชนีความซับซ้อน (CMI)

Coder ทำหน้าที่แปลบันทึกของแพทย์เป็นรหัส ICD-10 / ICD-9-CM เพื่อคำนวณค่า DRG (Diagnosis Related Group) และ CMI (Case Mix Index) หากแพทย์เขียนบันทึกไม่ครบถ้วน ค่า CMI จะต่ำกว่าความเป็นจริง ทำให้โรงพยาบาลสูญเสียรายได้จากการเบิกจ่ายชดเชย

การควบคุมโรคเบาหวาน

ร้อยละของผู้ป่วยโรคเบาหวานที่ควบคุมระดับน้ำตาลในเลือดได้ดี (HbA1c < 7%)

กลุ่มโรค NCDs

การควบคุมความดันโลหิตสูง

ร้อยละของผู้ป่วยโรคความดันโลหิตสูงที่ควบคุมระดับความดันโลหิตได้ตามเกณฑ์

อนามัยแม่และเด็ก

อัตราส่วนมารดาตาย

อัตราส่วนมารดาตายต่อแสนเด็กเกิดมีชีพ (Maternal Mortality Ratio)

อนามัยแม่และเด็ก

พัฒนาการเด็กปฐมวัย

ร้อยละของเด็กปฐมวัยที่มีพัฒนาการสมวัยจากการคัดกรองและกระตุ้นพัฒนาการ

ปฐมภูมิและผู้สูงอายุ

การประเมิน ADL & Care Plan

ร้อยละของผู้สูงอายุที่ได้รับการประเมิน ADL และได้รับการดูแลตาม Care Plan

ปฐมภูมิและผู้สูงอายุ

การคัดกรองมะเร็ง

ความครอบคลุมของอัตราการคัดกรองมะเร็งปากมดลูก และมะเร็งลำไส้ใหญ่

3.2 – 3.3 การนำข้อมูลไปวิเคราะห์และแสดงผลบน Dashboard (Data to Action)

การแสดงผลเป็นกราฟแท่ง กราฟเส้น หรือ Heat Map ช่วยให้ผู้บริหารและทีมระบาดวิทยาลงพื้นที่แก้ปัญหาได้ทันที:

1. กราฟอายุคาดเฉลี่ยเมื่อแรกเกิดและสถิติชีพ

ติดตามแนวโน้มอายุคาดเฉลี่ยของประชากรจังหวัดพิษณุโลก (ภาพรวม 77.44 ปี ชาย 73.92 ปี หญิง 81.01 ปี) เทียบกับเป้าหมายยุทธศาสตร์ชาติ 80 ปี

2. Dashboard คุณภาพข้อมูลสาเหตุการตาย

วิเคราะห์สัดส่วนการลงรหัสสาเหตุการตายไม่ชัดแจ้ง (Ill-defined เช่น R00–R99) แยกรายอำเภอและสำนักทะเบียน เพื่อยกระดับคุณภาพข้อมูล

3. ระบบเฝ้าระวังโรคเรื้อรังและระบาดวิทยา

ติดตามผู้ป่วยโรคไตวาย (ICD-10 N17–N19) รายเดือนและรายพื้นที่ รวมถึงการระบาดของโรคไข้เลือดออกเพื่อควบคุมแหล่งเพาะพันธุ์ยุงลาย

4. รายงานบริหารจัดการภายในโรงพยาบาล (Ward LOS)

รายงานจากระบบ HIS โรงพยาบาลพุทธชินราช เพื่อติดตามจำนวนผู้ป่วยในและวันนอนโรงพยาบาลเฉลี่ย (Length of Stay)

บทที่ 4 • MODULE 04

ความเสี่ยง ภัยคุกคาม และการบริหารจัดการระบบ

โรงพยาบาลเปิดให้บริการตลอด 24/7 หากระบบไอทีล่ม (Downtime) หรือถูกโจมตีทางไซเบอร์จะกระทบต่อความปลอดภัยของผู้ป่วยโดยตรง จึงต้องมีการควบคุมตามมาตรฐานสากล

4.1 ภัยพิบัติทางกายภาพ (Physical Threats) และแนวทางป้องกัน

1. อุทกภัย (น้ำท่วม)

การแก้ไข: ตั้ง Data Center บนชั้นสูงของอาคาร (หลีกเลี่ยงชั้นใต้ดิน/ชั้น 1) ติดตั้งระบบสูบน้ำ เซ็นเซอร์วัดความชื้น และสำรองข้อมูลบน Cloud นอกพื้นที่

2. อัคคีภัย (ไฟไหม้)

การแก้ไข: ห้ามใช้หัวฉีดน้ำ (Sprinkler) ในห้องเซิร์ฟเวอร์เด็ดขาด ต้องใช้ระบบดับเพลิงชนิดก๊าซ (FM-200 หรือ NOVEC 1230) และประตูทนไฟ

3. แผ่นดินไหว

การแก้ไข: ยึดตู้ Server Rack กับโครงสร้างอาคาร (Seismic Bracing) และมีศูนย์สำรองฉุกเฉิน (DR Site) ในพื้นที่ต่างรอยเลื่อนเพื่อสลับระบบทันที (High Availability)

4.2 ภัยคุกคามทางไซเบอร์และแฮกเกอร์ (Cybersecurity Threats)

Ransomware

มัลแวร์เรียกค่าไถ่

แฮกเกอร์เข้ารหัสฐานข้อมูลจนดูประวัติไม่ได้ การแก้ไข: ใช้กฎ Backup 3-2-1 (มีข้อมูล 3 ชุด, สื่อ 2 ประเภท, และเก็บแบบ Offline/Immutable 1 ชุด) ร่วมกับอัปเดต Patch

Data Breach

การโจรกรรมข้อมูลส่วนบุคคล

ขโมยข้อมูลผู้ป่วยไปขายในตลาดมืด นำไปสู่การฟ้องร้องตาม PDPA การแก้ไข: เข้ารหัสข้อมูล (Encryption) ติดตั้ง Next-Gen Firewall และจำกัดสิทธิ์ตามหน้าที่ (RBAC)

Phishing & Human Error

ฟิชชิ่งและวิศวกรรมสังคม

ส่งลิงก์ปลอมหลอกขโมยรหัสผ่านจากแพทย์หรือพยาบาล การแก้ไข: เปิดใช้การยืนยันตัวตนสองปัจจัย (2FA / MFA) และจัดอบรม Security Awareness เป็นประจำ

4.3 เทคนิคการโจมตีรหัสผ่าน (Password Cracking) 8 รูปแบบที่ควรรู้จัก

ลองนำเมาส์ชี้ที่การ์ดแต่ละใบเพื่อดูรายละเอียดของเทคนิคการโจมตีแต่ละรูปแบบ

TECHNIQUE 01

Dictionary Attack

การสุ่มเดารหัสผ่านจากไฟล์ที่รวบรวมคำศัพท์ต่าง ๆ ที่พบในพจนานุกรม

TECHNIQUE 02

Brute Force Attack

การไล่ลองทุกความเป็นไปได้ของตัวอักษรและตัวเลข รหัสที่สั้นจะถูกเจาะได้เร็วมาก

TECHNIQUE 03

Rainbow Table Attack

ใช้ฐานข้อมูลรหัสผ่านที่คำนวณค่า Hash ไว้ล่วงหน้า แล้วนำไปเทียบกับค่า Hash ที่ขโมยมา

TECHNIQUE 04

Phishing

หลอกให้ผู้ใช้กรอกรหัสผ่านเอง ผ่านอีเมลหรือข้อความแจ้งเตือนที่พาไปยังหน้าเว็บปลอม

TECHNIQUE 05

Social Engineering

หลอกลวงโดยอาศัยช่องโหว่จากพฤติกรรมผู้ใช้ เช่น โทรแอบอ้างเป็นเจ้าหน้าที่ IT เพื่อขอรหัสผ่าน

TECHNIQUE 06

Malware (Keylogger)

โปรแกรมดักจับทุกการพิมพ์คีย์บอร์ดหรือจับภาพหน้าจอขณะล็อกอินแล้วส่งให้แฮกเกอร์

TECHNIQUE 07

Offline Cracking

การขโมยไฟล์รหัสผ่าน (Hash) ออกไปถอดรหัสบนเครื่องของแฮกเกอร์เองโดยระบบตรวจจับไม่ได้

TECHNIQUE 08

Shoulder Surfing

การแอบมองรหัสผ่านขณะผู้ใช้กำลังพิมพ์ เช่น บริเวณเคาน์เตอร์พยาบาลหรือห้องตรวจ

4.4 มาตรฐาน ISO/IEC 27001:2022 (Annex A 93 Controls) และ ISO 27799

Annex A.5

Organizational Controls

การแบ่งแยกหน้าที่ (User Control Matrix), ทะเบียนทรัพย์สิน, นโยบาย AUP, แผน BCP/DRP

Annex A.6

People Controls

การคัดกรองประวัติบุคลากร (Screening), สัญญารักษาความลับ (NDA), การอบรมความตระหนักรู้

Annex A.7

Physical Controls

การควบคุมการเข้าออกห้อง Server, กล้องวงจรปิด, Clear desk & Clear screen

Annex A.8

Technological Controls

การสำรองข้อมูล (Backup), การเก็บ Log, การเข้ารหัส (Cryptography), การป้องกัน Malware

4.5 หลักความมั่นคงปลอดภัยสารสนเทศ 3 ประการ (C-I-A Triad)

C • CONFIDENTIALITY

ความลับของข้อมูล

ข้อมูลผู้ป่วยและระบบต้องถูกเข้าถึงได้เฉพาะผู้ที่มีสิทธิ์เกี่ยวข้องเท่านั้น

I • INTEGRITY

ความถูกต้องครบถ้วน

ข้อมูลเวชระเบียนต้องไม่ถูกแก้ไข ดัดแปลง หรือลบโดยมิชอบหรือโดยไม่ตั้งใจ

A • AVAILABILITY

ความพร้อมใช้งาน

ข้อมูลและระบบ HIS ต้องพร้อมใช้งานเสมอเมื่อแพทย์และบุคลากรต้องการใช้งาน

4.6 กฎหมายและหลักฐาน Log File

พ.ร.บ.ความมั่นคงปลอดภัยไซเบอร์ 2562, พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล (PDPA), พ.ร.บ.สถานพยาบาล และ พ.ร.บ.คอมพิวเตอร์ (ต้องเก็บ Log file ไม่น้อยกว่า 90 วัน) หน่วยงานรับแจ้งเหตุ: สกมช. และตำรวจไซเบอร์ สายด่วน 1441

4.7 กรณีศึกษาโรงพยาบาลถูกโจมตีไซเบอร์

กรณี รพ.สระบุรี ถูก Ransomware เข้ารหัสจนระบบคอมพิวเตอร์ขัดข้อง และกรณี รพ.เพชรบูรณ์ ถูกแฮกข้อมูลผู้ป่วย สะท้อนความสำคัญของการสำรองข้อมูลและแนวปฏิบัติเมื่อระบบล่ม (Downtime procedure)

บทที่ 5 • MODULE 05

บทบาทของบุคลากรทางการแพทย์ จริยธรรม และสรุป

การผสานศาสตร์ทางการแพทย์เข้ากับเทคโนโลยีสารสนเทศอย่างมีความรับผิดชอบ เพื่อประโยชน์สูงสุดในการดูแลผู้ป่วยและการพัฒนาระบบสาธารณสุข

01

เป็นผู้สร้างข้อมูลต้นทางที่มีคุณภาพ

บันทึกเวชระเบียนและสรุปคำวินิจฉัยอย่างครบถ้วน แม่นยำ มีความจำเพาะพอให้ลงรหัส ICD-10 / SNOMED CT ได้ถูกต้อง ส่งผลดีต่อการรักษาต่อเนื่องและการบริหารงบประมาณโรงพยาบาล

02

ปกป้องความเป็นส่วนตัวของผู้ป่วย (Patient Privacy)

เคารพสิทธิผู้ป่วยตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล (PDPA) ไม่ดูข้อมูลผู้ป่วยที่ไม่เกี่ยวข้อง ไม่นำประวัติหรือภาพถ่ายผู้ป่วยไปโพสต์โซเชียลมีเดีย ไม่แชร์รหัสผ่าน และ Log out ทุกครั้งเมื่อลุกจากเครื่อง

03

รักษาความมั่นคงปลอดภัยไซเบอร์ในชีวิตประจำวัน

ตั้งรหัสผ่านที่คาดเดายาก เปิดใช้งานการยืนยันตัวตนสองปัจจัย (2FA) ระวังอีเมลหรือลิงก์หลอกลวง (Phishing) และระวังการแอบมองรหัสผ่าน (Shoulder surfing) ในพื้นที่สาธารณะของโรงพยาบาล

04

นำข้อมูลไปใช้พัฒนาอย่างต่อเนื่อง (R2R)

นำข้อมูลเวชสถิติและตัวชี้วัดทางสุขภาพมาทบทวนกระบวนการทำงาน และต่อยอดเป็นงานวิจัยจากงานประจำ (Routine to Research: R2R) เพื่อยกระดับคุณภาพบริการสุขภาพปฐมภูมิ
